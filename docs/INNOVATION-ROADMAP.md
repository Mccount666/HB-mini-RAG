# 大创结项创新性与低成本迭代建议

更新时间：2026-09-10

## 一句话定位

本项目不是单纯把大模型接进小程序，而是面向肝母细胞瘤患儿家庭，构建了“导师终审知识库 + 可溯源问答 + 化验单 OCR 两段式解读 + 反馈学习队列”的低成本医学科普助手。

## 结项总结可强调的科普创新性

### 1. 从“泛化 AI 问答”转向“可控、可追溯的罕见病科普问答”

肝母细胞瘤属于儿童肿瘤中的相对少见疾病，家长常见问题集中在确诊、分期、化疗、手术、肝移植、复查随访和化验指标上。项目没有直接依赖大模型自由生成，而是先建设 167 条经导师终审的知识库，再通过检索增强生成回答，并要求回答附带来源。

可写入结项材料的创新点：

> 项目将大模型从“直接回答者”改造为“受知识库约束的科普表达器”，通过来源引用、数字溯源和拒答机制降低医学科普场景中的幻觉风险。

### 2. 引入“学习话术 + learn_queue”形成可持续知识积累闭环

当用户提出与肝母细胞瘤相关、但知识库暂未覆盖的问题时，系统不会编造答案，而是返回学习话术，并把问题写入 `learn_queue` 集合，供后续人工审核、补充知识库。

可写入结项材料的创新点：

> 项目把“不能回答”转化为“可积累的问题线索”，形成面向真实家长需求的知识库迭代机制，使科普系统具备持续改进能力。

### 3. 化验单 OCR 采用“两段式解读”，降低误识别造成的误导

化验单图片先经过 OCR 提取文字，前端展示给用户确认或修正，再进入 AI 解读。这样避免 OCR 把数值、单位、项目名称识别错后直接生成医学解释。

可写入结项材料的创新点：

> 项目在化验单解读中加入“用户确认 OCR 文本”的中间环节，把自动化识别与人工确认结合起来，兼顾便利性与医学安全。

### 4. 对医学数字进行溯源护栏

系统对带单位、小数、大于 20 的关键数字进行校验，要求它们能在知识库候选内容中找到出处；如果模型生成了没有出处的治愈率、剂量、时间等数字，就拒答并进入学习闭环。

可写入结项材料的创新点：

> 项目针对医学科普中风险最高的“数字幻觉”设置专门护栏，避免大模型随意生成治愈率、剂量和检查阈值。

### 5. 低成本部署路径

项目目前使用微信小程序 + 云开发云函数 + 文档数据库 + 云存储，知识库检索默认使用本地 embedding 方案，减少额外向量数据库和 embedding API 成本。大模型只在必要时调用，出范围问题和部分安全拦截不需要生成完整回答。

可写入结项材料的创新点：

> 项目采用轻量化架构，在不引入独立向量数据库和复杂后端运维的情况下，实现了面向专病科普的可溯源问答系统。

## 本轮已落地的小迭代

### 分层科普回答结构

本轮已将普通文本问答的提示词升级为“家长先看 / 进一步了解 / 就医提醒”的分层表达方式，并同步到云函数目录。该改动不新增数据库、不新增云服务、不引入额外模型调用，只通过提示词约束改善科普表达质量。

已同步的质量保障：

- `backend/src/rag/prompt.js` 与 `cloudfunctions/qa/src/rag/prompt.js` 已保持一致。
- `tools/smoke.js` 已增加“分层科普结构可用”断言，防止后续迭代把该能力意外改掉。
- 冒烟测试已覆盖：范围内回答、拒答、无引用重试、无出处数字拦截、追问、OCR 解读。

结项表述可写：

> 项目进一步探索了面向患儿家长的分层科普表达策略，将回答组织为“家长先看、进一步了解、就医提醒”三个层次，帮助不同健康素养水平的家长快速获得关键信息，同时保留医学背景解释和就医安全边界。该策略主要通过提示词和测试约束实现，成本低、可维护性好。

### 家长问题地图与来源卡片

本轮已将“家长问题地图”从结项建议推进为最小可用实现：小程序会根据提问关键词自动标注科普需求主题，例如“确诊检查”“化验指标”“化疗护理”“手术移植”“随访复查”“居家护理”“预后风险”“危险信号”等。主题标签会显示在用户问题气泡上，并随本地历史记录和反馈记录一起保存。

同时修复了本地后端反馈管理接口的统计问题：过去反馈写入文件成功后仍保留在内存数组中，管理端读取时可能把同一条记录重复计数。现在仅在文件写入失败时才使用内存兜底，并在管理端返回 `topicStats` 主题分布，便于后续直接生成“家长高频问题分布图”。

来源展示也升级为“来源卡片”：点击回答下方来源时，不只展示摘要，还会说明“为什么引用这条”，帮助家长理解回答依据，提升医学科普信息透明度。

结项表述可写：

> 项目进一步建立了“提问—主题归类—反馈统计—知识补充”的需求发现闭环。系统通过轻量规则对家长问题进行主题标注，并在反馈管理端汇总形成科普需求分布，为后续知识库增补和科普专题建设提供依据。该方案不依赖额外模型调用和复杂数据平台，成本低、可解释性强，适合在专病科普场景中推广。


## 下一阶段最推荐的低成本迭代方向

### A. 增加“家长问题地图”：把真实问题自动归类成科普需求图谱

优先级：高  
成本：低  
难度：低到中  
适合大创结项展示：很适合

做法：

1. 从 `feedback` 和 `learn_queue` 中导出问题。
2. 按主题做半自动分类：确诊检查、治疗方案、化疗副作用、手术/移植、化验指标、随访复查、饮食护理、心理支持、费用与就医路径等。
3. 在结项报告中展示“家长高频问题分布图”。
4. 小程序后续可增加“问题分类入口”或“专题科普卡片”。

创新性表达：

> 项目不只提供问答，还能从用户提问中反向发现患儿家庭的信息需求，形成“需求驱动”的专病科普内容建设模式。

为什么推荐：

- 不需要改复杂模型。
- 不增加明显云资源成本。
- 很容易做成结项图表。
- 能体现用户需求分析和医学传播价值。

### B. 增加“分层科普回答”：先给家长版，再给进阶版

优先级：高  
成本：低  
难度：中  
适合大创结项展示：很适合

做法：

在回答结构上增加两层：

1. “家长先看”：用短句解释结论和下一步建议。
2. “进一步了解”：展开医学术语，如 PRETEXT、AFP、CHIC、顺铂耳毒性等。

示例：

```text
家长先看：AFP 是肝母细胞瘤随访中很重要的指标，但不能单独决定病情。
进一步了解：AFP 需要结合年龄、治疗阶段、影像检查和医生判断一起看……[来源1]
```

创新性表达：

> 项目尝试将专业医学知识转化为分层阅读内容，兼顾低健康素养家长的快速理解和有进一步学习需求家长的深入阅读。

为什么推荐：

- 主要改 prompt 和前端展示，不需要新服务。
- 对医学科普价值非常直观。
- 结项答辩时容易演示。

### C. 增加“化验指标趋势记录”但不做诊断

优先级：中  
成本：中  
难度：中  
适合大创结项展示：适合，但要注意边界

做法：

1. 用户每次上传化验单后，可选择保存 AFP、白细胞、血红蛋白、血小板、ALT、AST、胆红素等结构化指标。
2. 小程序展示简单趋势线。
3. 文案明确：趋势图仅供复诊沟通，不用于诊断。

创新性表达：

> 项目将一次性化验单解读扩展为“随访沟通辅助”，帮助家长整理复查数据，提高医患沟通效率。

风险控制：

- 不给“好转/恶化”的自动诊断结论。
- 只提示“请带趋势图咨询医生”。
- 需要更严格的隐私提示和数据删除入口。

是否现在做：

如果时间充足可以做最小版；如果结项时间紧，建议只写为未来展望，不必立刻实现。

### D. 增加“拒答质量分析”：证明系统知道自己不能答什么

优先级：中  
成本：低  
难度：低  
适合大创结项展示：适合

做法：

把测试集分为：

1. 范围内问题。
2. 近邻但不应回答的问题，例如普通感冒、糖尿病、乙肝疫苗价格。
3. 完全无关问题，例如天气、理财。
4. 幻觉诱导问题，例如“治愈率是不是 99%”。

展示系统在这些问题上的通过率、拒答率和引用率。

创新性表达：

> 医学科普 AI 的关键能力不仅是“会回答”，还包括“知道何时不回答”。项目将拒答能力作为质量评价指标之一。

为什么推荐：

- 你们已经有 `tools/eval.js`、`tools/smoke.js`、`tools/qa-gw-test.js` 基础。
- 很适合放进结项论文/报告的方法学部分。

### E. 增加“来源卡片可读化”

优先级：中  
成本：低  
难度：低  
适合大创结项展示：适合

做法：

现在回答有来源，但家长可能不一定点开或理解。可以把来源展示改成更友好的卡片：

- 来源标题
- 一句话摘要
- 所属主题标签，如“化疗护理”“AFP”“随访”
- “为什么引用这条”说明

创新性表达：

> 项目不仅提供答案，还展示答案依据，提升家长对医学科普信息来源的理解和信任。

## 不建议优先做的方向

### 1. 不建议做复杂多智能体医疗助手

原因：

- 成本和复杂度上升明显。
- 医疗安全边界难控。
- 大创结项不一定需要展示复杂 Agent 架构。

### 2. 不建议接入过多外部医学数据库自动更新

原因：

- 自动抓取医学内容需要版权、时效性和审核流程。
- 没有导师审核会削弱项目现在的安全亮点。

更好的说法是：

> 后续可探索“人工审核后增量入库”的半自动更新机制。

### 3. 不建议让系统输出个体化治疗建议

原因：

- 风险高。
- 容易越过科普边界。
- 小程序提审和结项答辩中都可能被质疑。

应坚持：

> 提供健康科普和复诊沟通辅助，不替代医生诊断和治疗决策。

## 最推荐的结项展示组合

如果要兼顾创新性、成本和完成难度，建议结项重点包装为下面四件事：

1. 167 条导师终审知识库：体现医学内容质量。
2. 可溯源 RAG 问答：体现 AI 科普创新。
3. 化验单 OCR 两段式解读：体现应用场景创新。
4. 反馈与学习队列：体现持续迭代机制。

如果还能再做一个小迭代，最推荐做：

> “家长问题地图 + 分层科普回答”。

这两个方向实现成本低，但在结项材料中非常好讲：一个体现真实需求分析，一个体现医学知识转化能力。

## 可直接放进结项报告的总结段落

本项目围绕肝母细胞瘤患儿家庭在诊疗过程中的高频信息需求，构建了一个低成本、可追溯、可迭代的专病科普小程序。项目以导师审核知识库为核心，通过检索增强生成技术约束大模型回答范围，并结合来源引用、数字溯源、拒答机制和学习队列，降低医学科普场景中的幻觉风险。在应用层面，项目进一步探索了化验单 OCR 两段式解读，将图片识别、用户确认和安全解读结合起来，为家长复诊沟通提供辅助。与通用问答工具相比，本项目的创新性主要体现在专病知识库建设、面向家长的分层科普表达、医学数字安全护栏以及基于真实提问的知识持续更新机制。整体架构依托微信小程序和云开发能力实现，无需复杂运维和昂贵向量数据库，具有较好的可推广性和大创项目落地价值。
