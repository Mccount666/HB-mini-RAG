## 二、最小化幻觉的六条防线（文本问答）

| 防线 | 位置 | 机制 |
|------|------|------|
| 1. 混合检索 | retriever.js + bm25.js + synonyms.js | 向量余弦（语义相近）与 BM25（术语精确命中）加权融合；医学同义词表把家长口语（AFP/肚子胀/换肝）映射到知识库术语，弥补本地向量对医学术语的弱语义 |
| 2. 检索优先 | answer.js | 先检索知识库，再决定是否调用大模型；无相关条目直接拒答 |
| 3. 置信度门控 | retriever.js + config | `STRICT_RETRIEVAL=true` 时，top 命中**融合分** < `RETRIEVAL_THRESHOLD` 则**不调大模型**，返回固定拒答话术 |
| 4. 严格提示词 | prompt.js | 系统提示词规定"仅依据`<知识库>`作答、强制`[来源N]`引用、数字必须与原文逐字一致、无内容必拒答、不得给诊断/剂量" |
| 5. 生成后护栏 | guard.js | 机检模型输出：越界 `[来源N]` 剔除；关键数字（带医学单位/含小数/大于20）必须能在命中条目中找到原文，否则**整条拒答**；无引用时带强化指令重试一次，仍无引用则拒答。医学安全优先：宁可不答，不可错答 |
| 6. 来源可溯 | sources 字段 | 每条回答回传引用条目（id/title/excerpt），前端点击可查看出处，便于家长核对与运营纠错 |

> 阈值 `RETRIEVAL_THRESHOLD` 是控幻觉的核心旋钮。过低 → 容易答非所问（幻觉上升）；
> 过高 → 召回变少、误拒率上升。**改任何检索配置后必须用 `node tools/eval.js` 重跑校准**。
> **实测校准**（本地哈希向量化 + BM25 融合，2026-08）：范围内 16 题融合分 0.395–0.670、
> 门控全通过；出范围 10 题中 7 题被拦截（分数 0.084–0.344），3 题近邻问题（糖尿病饮食等）
> 放行后由严格提示词 + 护栏拒答；默认阈值 **0.35**。
> 若改用 API embedding，默认 0.45，并重新跑 eval 标定。

### 近邻问题的处理策略

"糖尿病饮食注意什么""乙肝疫苗什么时候打"这类问题与知识库共享表面词（饮食/疫苗），
检索层无法与真问题统计分隔（实测两者词法/向量分均不低）。设计上**不在检索层硬拦**——
那会误杀口语化的真问题——而是放行进大模型，由第 4、5 道防线（严格提示词 + 数字/引用护栏）
拒答。若日志中发现近邻问题被错误作答，优先补充知识库或调高阈值，并跑 eval 验证。

## 三、化验单 OCR 解读设计（严格基于诊断标准）

化验单解读同样坚持"检索增强 + 严格提示词 + 来源可溯"，并额外做两件事：

1. **识别与解读解耦**：DeepSeek 无视觉能力，化验单识别必须走独立 OCR 服务（默认 `mock` 免 key 演示，生产切 `tencent` 腾讯云 OCR）。解读仍由大模型完成。
2. **只在化验参考区间内检索**：`interpret.js` 调用 `retrieve(embedding, { category:'lab_reference' })`，
   只取"化验单参考区间"分类（约 14 条），且 `ocrTopK=50 / ocrThreshold=0` 把**全部参考条目**作为上下文 grounding，
   保证 AFP、ALT、WBC 等每条异常值都能被引用、且严格基于参考区间，而非模型自由发挥。
3. **提示词铁律**（`prompt.buildOcrMessages`）：仅依据 `<参考标准>` 与化验单原文数值解读；
   **以化验单上标注的参考区间为准**，与参考标准不一致时提示"以就诊医院报告为准"；
   不给药剂量、不给诊断结论；无法识别时明确说明。
4. **引用护栏**（`guard.validateCitations`）：解读中的越界 `[来源N]` 引用被剔除
   （数字溯源不适用于 OCR——报告数值来自家长上传的化验单本身）。
5. **来源可溯**：解读回传命中的化验参考条目，前端"参考来源"标签可点开。

> 化验参考区间（`lab_reference.json`）以"主流诊断标准"编写，但不同实验室/年龄/性别有差异，
> 且婴幼儿 AFP 呈生理性升高——上线前务必由导师核对为本院/本实验室实际区间。解读提示词已强制"以报告单标注区间为准"。

## 四、前端关键设计

- **纯 Chat 定位**：本小程序仅作为问答工具——文本问答 + 化验单 OCR 解读，不做复查提醒、不做订阅消息、不绑定其他业务。
- **参考来源可视化**：`chat-message` 组件把 `sources` 渲染成可点击的 `[1] 标题` 标签，点开看摘要。
- **化验单消息**：用户侧显示化验单缩略图，bot 侧显示解读 + 可折叠"识别原文" + 来源。
- **轻量历史**：本地 `wx.storage` 存最近 200 条，离线可看。
- **免责常驻**：首页顶部常驻免责条，须知页详述"不能替代医生诊断"。
- **性能**：`lazyCodeLoading: requiredComponents` 减少主包启动开销；主包仅含三页，远低于 2MB。

## 五、包体与扩展规划

- 当前主包极小，远低于 2MB 限制。
- 向量库升级路径：本地 JSON 索引仅适合中小知识库；条目过万或需高并发时，迁移到
  **腾讯云向量数据库 / pgvector / Milvus**，检索层 `retriever.js` 接口不变即可平滑替换。
- OCR 服务升级：默认 `mock` 仅用于演示；生产在腾讯云控制台开通「文字识别」并填 `TENCENT_SECRET_ID/KEY`，
  改 `OCR_PROVIDER=tencent` 即可接真实识别，无需改业务代码。

## 六、上线与获客建议

1. **公众号绑定**：在"肝芽守护"公众号图文里嵌小程序卡片，把科普读者直接转成问答用户。
2. **分享裂变**：问答/解读结果页支持转发，家长群天然传播场景。
3. **视频号联动**：短视频/直播挂小程序链接，承接"刚确诊、一脸懵"的流量。

> 注：本版本**不含复查提醒与订阅消息**（按需求仅保留纯 Chat）。后续若确需，再按 subpackage + `wx.requestSubscribeMessage` 评估。
