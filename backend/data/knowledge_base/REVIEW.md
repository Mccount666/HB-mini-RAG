# 知识库审核流程（导师终审）

本目录下的每一条问答都会直接面向患儿家长，内容准确性事关重大。上线前，**每一条都必须由科室高年资医生（导师）终审通过**。

## 条目结构
每条问答是一个 JSON 对象：
```json
{
  "id": "HB-001",            // 唯一编号，建议按分类递增
  "category": "疾病科普",     // 分类标签，便于检索与统计
  "question": "肝母细胞瘤是什么？",
  "answer": "……权威、通俗、可核对的描述……",
  "source": "《xxx 诊疗规范》/ 科室共识 / 公众号文章链接",
  "reviewed": false,         // 终审通过后改为 true
  "reviewedBy": "",          // 填审核人姓名/工号，如 "李XX"
  "reviewedAt": ""           // 填审核日期，如 "2026-08-10"
}
```

## 审核清单（导师逐条核对）
- [ ] 事实准确，与最新诊疗规范/科室共识一致
- [ ] 无诊断性结论、无具体用药剂量（仅科普与就医引导）
- [ ] 表述通俗、对焦虑家长温和
- [ ] `source` 可追溯（规范/文献/共识，而非"网上说的"）
- [ ] 通过后在 JSON 中把 `reviewed` 改为 `true`，并填 `reviewedBy` / `reviewedAt`

## lab_reference 参考标准例外（2026-09-04）

lab_reference.json 的 14 条（LAB-AFP~LAB-CREA）是**客观检验参考区间标准数据**，
仅供 OCR 化验单解读检索使用，不属于面向家长的科普问答。为使上线门控
（`KB_ONLY_REVIEWED=true`）不破坏 OCR 解读管线，这 14 条已标注
`reviewed=true / reviewedBy=参考标准入库`。**注意**：其 source 字段仍保留
「待导师核对具体实验室标准」，导师复核各实验室标准后方可视为完全终审。
其余分类（疾病科普/治疗/随访等）的条目**不适用本例外**，仍须导师逐条终审。

## 审核状态查询
```bash
node tools/kb-status.js
```
会列出：总条数、已审核数、待审核清单。把待审核清单交给导师逐条过即可。

## 上线门控（关键安全开关）
审核全部通过后：
1. 在 `backend/.env` 设置 `KB_ONLY_REVIEWED=true`
2. 重新生成索引：`npm run ingest`
3. 同步到云函数：`node tools/sync-cloudfunction.js`
此后检索库**只包含导师已审核内容**，未审核的演示数据不会流向家长。

## 新增 / 修改条目
- 直接编辑本目录下的 `.json` 文件，或在「肝芽守护」科普文章基础上结构化后新增。
- 改完跑一次 `node tools/kb-status.js` 确认状态。
- 重新 `npm run ingest` + 同步云函数，使改动生效。
